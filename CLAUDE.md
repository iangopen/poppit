# Poppit

Single-file browser idle/clicker game: pop pearls for juice, buy upgrades, Fresh Batch (prestige) for Flavors. Hosted on GitHub Pages straight from `index.html` on `main`.

## Reporting to Ian

- **Every session ends by writing its final summary to `docs/last-session.md`** (plain text, overwritten each time) and printing the same text. Ian attaches that file in chat, because pasted terminal text gets mangled.
- **Final summaries are plain bulleted text:** no tables (Markdown or box-drawing), and every line under 100 columns. Ian pastes them into a chat, where tables break. Put tables in files such as `docs/balance-report.md`, not in the summary.

## Architecture contract

- **`index.html` is a build output.** Never edit it by hand; edit `src/` and rebuild. It is committed because Pages serves it.
- **Standalone page rules.** `index.html` is served as is by GitHub Pages, with no wrapper, so it must be a complete document. `tests/page.test.js` checks all of this:
  - `src/head.html` opens the document: `<!doctype html>`, `<html lang="en">`, `<head>`, `<meta charset="utf-8">` first (it must stay within the first 1024 bytes), then the viewport meta `width=device-width, initial-scale=1, viewport-fit=cover`, `<title>`, the font links, `<style>`, `</head>`, `<body>`, the markup, and finally an open `<script>`.
  - `src/tail.html` closes it: `</script>`, `</body>`, `</html>`.
  - Without the doctype the page falls into quirks mode. Without the charset, a server that sends no charset (such as `python -m http.server`) shows "Â·" for "·".
  - **The hidden rule:** the CSS starts with `[hidden] { display: none !important; }`. Panels, rows, slots and the Restore row are all shown and hidden with the `hidden` attribute, so never give one a `display` that beats it some other way.
  - Inline SVG icons inside buttons need `display: block` where their box matters. Standards mode adds a baseline gap under inline images; the book arrows had one.
  - `tools/build.js` stays a plain byte concatenation.
- **Concat order (fixed):**
  - `src/head.html`
  - then `src/artifacts.js`, `forge.js`, `econ.js`, `save.js`, `samples.js`, `audio.js`, `music.js`, `world.js`, `render.js`, `ui.js`
  - then `src/tail.html`
  - The JS files share one scope inside the page, so later files use earlier files' top-level names.
  - `tests/harness32.js` repeats this list. Keep the two lists in step with `tools/build.js`.
- **`src/artifacts.js`** (`ARTS`) holds artifacts, pure with no DOM. It comes first in the concat order because `econ.js` uses it; under node, `econ.js` `require`s it. Design note: `docs/superpowers/specs/2026-10-21-artifacts-hall-of-ducks-design.md` (the copy model below replaced its "owned or not").
  - `HALLS`: `{ id, name, blurb }` in display order: `ducks` (Hall of Ducks) and `relics`, named by `RELIC_HALL_NAME` ("Hall of Relics", one string).
  - `ARTIFACTS`: `{ id, hall, name, description, cost: [{ kind, qty } | { kind: 'material', id, qty }], repeatFactor, costGrowth, bonus: { type, value } }`.
    - A pearl cost line's `kind` is a pearl id; only normal stacks count, so a shiny Rose (`pearl:s`) is not a Rose Pearl. A material line spends dusts or alloys from `state.forge.stock`.
    - **Repeat crafts** (`craftCost`): the first copy costs `qty`; every later one costs `ceil(qty × repeatFactor × costGrowth^(copies owned - 1))`. Both fields default to 1. The Pink Duck has repeatFactor 0.25 (10,000, then 2,500 each); every relic has 1. Every costGrowth is 1 today.
    - `bonus.value` is a multiplier. Payout bonuses multiply; every other stat adds `value - 1`.
  - **Pink Duck:** `pink_duck`, hall `ducks`, 10,000 `pearl` (Rose) for the first copy and 2,500 for each later one, payout × `PINK_DUCK_PAYOUT` (1.4; one constant).
  - **Hall of Relics** (alloys only, utility only, untuned):
    - Rose Lantern: 2 Rosegold; frenzy meter fills 25% faster (`meter` x1.25).
    - Blue Compass: 2 Azure Steel + 1 Rosegold; forge speed x1.3.
    - Mint Clock: 2 Mintsilver + 1 Azure Steel; away bonus x1.2.
    - Relics are assembled at the hall, instantly, like the duck. The forge makes only dusts and alloys.
  - **Copies and the pedestal.** `state.artifacts` is `{ <artifact id>: { copies: [{ id, art, rarity, perks: [{ stat, value }], paid: [cost lines], locked }], active: <copy id> } }`.
    - Copy ids are whole numbers, unique across all artifacts (`nextId` = highest + 1).
    - Every craft adds a copy, owned or not. The first copy of an artifact goes on the pedestal (`active`) by itself; later copies never replace it.
    - `setActive(arts, id, copyId)` swaps freely, at any time, for nothing. The game hook is `setActiveCopy(id, copyId)` in `src/ui.js` (recalc, refresh, save); the shelf's Place buttons and the reveal's Place on pedestal call it.
    - **Only the active copy counts:** its artifact's base bonus plus its perks.
  - **Rolls** (`roll(rng)`, the rng is injectable; the game uses `Math.random`). The result is stored in the copy, so a load never re-rolls.
    - `RARITIES` (retuned 2026-10-22): Common 55% (0 perks), Rare 30% (1, values x1), Epic 12% (2, values x1.5), Mythic 3% (3, values x2.5).
    - `PERKS` (value = added fraction, rolled in min..max, times the rarity's range, never above cap; a copy's perks are distinct stats):
      - payout 0.02-0.06, cap 0.20 (payouts × (1 + value));
      - shiny 0.05-0.15, cap 0.40 (shiny chance × (1 + sum));
      - frenzy 0.05-0.15, cap 0.40 (frenzy length);
      - away 0.05-0.15, cap 0.40 (away bonus rate);
      - forge 0.05-0.15, cap 0.40 (forge speed);
      - spawn 0.03-0.08, cap 0.20 (spawn rate).
      - A top Mythic roll (max × 2.5) never reaches a cap, so the caps only clamp loaded saves. Saves made under the old caps (0.10 / 0.25 / 0.12) load unchanged.
  - `activeBonuses(arts)` is the one function that sums active bonuses: `payout` as one multiplier (the duck's x1.4 times every active payout perk), and `shiny`, `frenzy`, `away`, `forge`, `spawn`, `meter` as added fractions. `payoutMult(arts)` is its payout.
  - `canCraft(id, inv, arts, stock)`; `craft(id, inv, arts, invV, stock, rng)` spends exactly `craftCost` (and the same share of a pearl stack's stored value) and returns the new copy, or `null` and changes nothing.
  - **Paid cost:** every copy stores `paid`, the cost lines actually spent when it was crafted (`craft` passes them to `addCopy`; `addCopy` without them records the next craft's price). Refunds read `paid`, never today's price, so a later change to `repeatFactor` or `costGrowth` cannot make crafting cheap and scrapping dear.
  - **Locks:** `locked` per copy. New copies take their rarity's `lockNew` (Epic and Mythic `true`, Common and Rare `false`). `setLocked(arts, id, copyId, on)` works at any time, on any copy, the pedestal copy included.
  - **Scrap:** `scrap(arts, id, copyId, inv, stock)` removes a shelf copy and refunds `floor(REFUND_SHARE × qty)` of each `paid` line (`refundOf(copy)`), pearls into `inv` (the backpack), materials into `stock`. It returns the refund lines (a qty may be 0), or `null` and changes nothing. `scrapBlock` names why not: `'pedestal'` (the active copy can never be scrapped), `'locked'` or `'missing'`.
    - `REFUND_SHARE` = 0.4, one constant in `src/artifacts.js`.
    - At today's prices a repeat duck refunds 1,000 Rose Pearls, the first duck (paid 10,000) 4,000, and **every relic refunds nothing**: 40% of 1 or 2 alloys floors to 0.
    - Ids are highest + 1, so after scrapping the newest copy the next craft reuses its id. Ids stay unique among owned copies.
  - `fromSave(d)` clamps a loaded `artifacts`: unknown artifact ids, copies with an unknown rarity or a bad or repeated id are dropped; perks keep known, distinct stats, at most the rarity's count, values clamped to min..cap; an `active` that is not an owned copy falls back to the first copy. `paid` keeps one line per artifact cost line (same kind, and id for materials), whole, from 0 up to the most any copy in that save could have paid (base × max(1, repeatFactor × costGrowth^(copies - 1))); a missing or bad line becomes the repeat price. `locked` is true only for a real `true`.
  - Add an artifact with a table entry and, for its card and reveal, an icon in `ART_ICON` (`src/ui.js`): the duck, a lantern, a compass and a clock today.
- **Where the active bonuses land:** `stats()` calls `activeBonuses` once and every reader goes through `S`:
  - `artMult` (payout): `popValue()` and `helperIdle()`, so taps, sweeps, helpers, shinies, frenzy, auto-sell, backpack value and the away bonus;
  - `shinyBonus`: `shinyChance(L, bonus)` in spawning (`src/world.js`), the shop and pool text, and `helperIdle`;
  - `frenzySecs` (`FRENZY_SECS × (1 + frenzy)`): `startFrenzy`, the meter bar and `helperIdle`;
  - `meterMult`: every meter fill (tap 1, helper `HELPER_METER`) and `helperIdle`;
  - `awayShare` (`AWAY_SHARE` 0.5 × (1 + away)): `awayBonus()`;
  - `spawnEvery` is divided by (1 + spawn);
  - `forgeBonus`: `recalc()` passes it to `FORGE.setBonus`, which re-times running jobs.
  - The payout line under the juice counter reads e.g. "Payouts x1.68 (Flavors 2 x1.2, artifacts x1.4)".
- **Keep** (`state.keep`, pearl type id → `true`):
  - A kept type covers its shiny stack too (`isKept(kind)` in `src/world.js`).
  - Its pops go to the backpack even with auto-sell on.
  - Sell all, the Worth total and the Sell all button skip kept stacks. Selling a kept stack by choosing it still works.
  - The toggles are rows in the backpack's "Keep for crafting" list: one per discovered type, shown even with nothing held. Kept stacks carry a small padlock.
- **Artifacts panel** (`#arts`, `updateArts()`, data from `artView()`): a large panel like Pool.
  - **Layout:** the header, then one tab per hall (`#artTabs`, `setArtTab(id)`, built from `HALLS`), then one scrolling body: the pedestal line, the intro, the material line and the selected hall's cards. The tab is remembered while the page is open.
  - **Pedestal line** (`#artSum`, `pedestalLine()`): every active copy and their combined effect from `activeBonuses`, e.g. "On your pedestals: Pink Duck (Mythic), Rose Lantern (Rare). Together: Payouts x1.54, Away bonus +10%, Frenzy meter speed +25%." With none: "Nothing on a pedestal yet. ...".
  - **Unowned card:** icon, name, effect, cost lines with bars (pearl lines "x of 10,000 Rose Pearls kept"; material lines through `FORGE.costText`, "1 of 2 Rosegold"), the odds hint, the disabled reason and Craft.
  - **Owned card:** framed in the active copy's rarity colour. The icon stands on a small pedestal drawing with an "On pedestal" badge, then "<Rarity> copy", "Base: <effect>", its perks in plain words ("Payouts +6.4%") or "No perks", then "Next copy costs" with the repeat cost lines, the odds hint, the reason and **Craft another**.
  - **Shelf** (`shelfView`, `shelfHTML`): every copy off the pedestal.
    - **Common stack:** all shelf Commons share one row, "Common x12" (they have no perks). Every other copy has its own row.
    - **Sort:** "Best first" (rarity, then oldest; the default) or "Newest first" (`shelfSort`, a page-session choice, not saved). A stack sorts by its newest copy.
    - Each row shows its perks, what placing it changes ("Placing it: Payouts x1.4 → x1.54, Shiny chance +0% → +25%"), and what scrapping gives ("Scrap: +1,000 Rose Pearls", "Scrap: no refund", or "Locked: unlock it to scrap").
    - Buttons (`data-sact` = `place`, `lock`, `scrap`, `scrapall`, with `data-art` and `data-copy`, a copy id or `stack`):
      - **Place** calls `setActiveCopy` and toasts; on a stack it places the newest Common.
      - **Lock / Locked** toggles; on a stack it locks every Common if any is unlocked, else unlocks them all.
      - **Scrap** is disabled while locked. On a stack it scraps the newest unlocked Common, with no question. A Rare also goes at once. **Epic and Mythic ask first.**
      - **Scrap all N** on a stack (N unlocked Commons, shown when N > 1) asks first; locked Commons stay.
    - **Bulk:** "Scrap all unlocked below <pedestal rarity> (N)" (`data-bulk`, `bulkScrap`, `bulkTargets`) shows when N > 0. It takes every unlocked shelf copy of a lower rarity than the pedestal copy, after a confirmation that names the count and the total refund ("Scrap 4 copies below Mythic? 4 unlocked Pink Duck copies go for +7,000 Rose Pearls. ...").
    - After any scrap a toast reports it: "Scrapped 4 Pink Duck copies: +7,000 Rose Pearls" (or "(no refund)").
    - **Where refunds go** (`scrapCopies`): Rose Pearls into the backpack as kept stock. Auto-sell only ever sells new pops, so it never touches them, and Sell all skips them while Rose is kept. Keep is not switched on by a scrap. Refunded pearls carry the stack's average stored value, or a fresh pop's value if the stack was empty. Alloys go into the forge stock.
    - Rows wrap, every shelf button is at least 44 px tall, and the rows scroll inside the card past 420 px.
  - **Confirmation** (`#confirm`, `openConfirm(title, text, okText, onOk)`, `closeConfirm(ok)`): an in-page dialog, never a browser dialog. Focus starts on Cancel, Tab and Shift+Tab stay on its two buttons, Escape or a tap outside the box cancels (and does not close the panel), and focus returns to where it was.
  - **Odds hint** (`oddsText()`): built from `RARITIES` weights, never hard-coded: "Each craft rolls Common 55%, Rare 30%, Epic 12%, Mythic 3%".
  - **Disabled reason** (`craftReason(id)`): the first short cost line. "Need 1,500 more Rose Pearls in your backpack"; with auto-sell on and the type not kept, "Need 1,500 more Rose Pearls: turn on Keep for them in your backpack"; for a material, "Need 1 more Rosegold: make it in the forge". The button's `title` carries it too.
  - Rarity colours are CSS classes `.r-common`, `.r-rare`, `.r-epic`, `.r-mythic` (`--rc` frame and glow, `--rt` darker text for contrast, `--go` glow strength, `--gl` glow size). A new rarity needs a class.
  - The dock button (`#artBtn`, an inked duck) shows once Rose Pearls popped in total (normal + shiny) reach 100, or once any copy is owned.
  - **Gated dock buttons** use one table, `DOCK_GATES` in `src/ui.js`, keyed by `PANEL_BTN` panel ids (`arts`, `forge`), and `syncDock()` checks them every HUD tick. While a gated button shows, the stage carries its id as a class (`#stage.arts`, `#stage.forge`), which moves the bottom bar right on wide screens.
  - The dock order is pack, tools, book, Artifacts (202 px), Forge (258 px).
- **Roll reveal** (`#reveal`, a full-screen dialog after every craft; `openReveal`, `revealTick`, `skipReveal`, `closeReveal`, `placeFromReveal`, data from `revealView()`):
  - It shows the icon, the artifact name, the rarity name in its colour, a glow and particles that grow with rarity (`REVEAL_PARTS` 8 / 16 / 28 / 44, on fixed angles, never `Math.random`), then the perks one by one (`REVEAL_FIRST` 0.7 s, then every `REVEAL_GAP` 0.55 s), driven by the main loop so tests can step it.
  - When done it shows the compare line against the copy that was on the pedestal before the craft: "Payouts x1.54 vs your current x1.4; Shiny chance +25% vs your current +0%", or "The same stats as the copy on your pedestal".
  - Buttons: **Place on pedestal** and **Keep on shelf**. The first copy of an artifact is already placed, so it shows "Placed on your pedestal: <effect>" and one "Nice!" button.
  - A tap anywhere but a button skips to the end; a tap on a finished reveal closes it. Escape closes it at any point (the copy stays on the shelf) and does not close the panel behind. Tab and Shift+Tab stay on its buttons; focus starts on Place (or Nice!) and returns to where it was.
  - **Reduced motion** (`calm`): every perk shows at once, no particles, no animations (CSS `prefers-reduced-motion` rule too).
  - **Sound:** `Snd.chime(rank)` in `src/audio.js`, a rising triangle arpeggio of 3, 5, 7 or 9 notes (plus a high note from Epic up), made with the existing `tone()` synth, so it is silent when Sound is off. Each perk that appears ticks. No audio files.
  - The craft toast is gone: the reveal says it all. Placing from the shelf or the reveal toasts "Pink Duck (Mythic) is on your pedestal".
- **`src/forge.js`** (`FORGE`) is the forge engine: pure, no DOM, every number is data.
  - Recipes are `{ inputs: [{ kind: 'pearl' | 'material', id, qty }], secs }`. Both tiers are just recipes: jobs, slots, speed, Strike, offline finish and the save format are the same.
  - `MATERIALS` (dusts): one per pearl type, in roster order, each with one pearl input.
    - Rose Dust (100 Rose, 30 s), Blue Dust (70, 1 min), Mint (45, 2 min), Golden (30, 4 min), Violet (20, 8 min).
    - Coral (14, 16 min), Marble (10, 32 min), Opal (7, 64 min), Ruby (5, 2 h 8 min), Black Dust (3 Black, 4 h 16 min).
    - The quantity falls and the time doubles per position; tests hold those two rules, not the exact numbers.
  - `ALLOYS` (untuned): Rosegold (6 Rose Dust + 2 Blue Dust, 2 min), Azure Steel (4 Blue Dust + 2 Mint Dust, 5 min), Mintsilver (4 Mint Dust + 2 Golden Dust, 10 min).
  - `ALL` = dusts then alloys. Alloys sit in the same `stock` as dusts; `byId`, `fromSave`, the stock line and `costText` cover both.
  - `missing(f, matId, inv)`: the first short input `{ kind, id, qty, have, short, name }` (name set for materials), or null. `canStart` uses it.
  - `fromScratch(matId)`: the pearls and serial forge seconds behind a material at rate 1 (used for the reports).
  - Forge state is `state.forge = { slots, stock, lv: { speed, slot }, rate, frenzy, bonus, strikes }`. The last four are live only and never saved.
  - A job is `{ mat, start, end }` in ms (`Date.now()`). `start()` takes every input at once: normal pearls from the backpack (and their share of `invV`), materials from the stock.
  - A job is done when `now >= end`. `finish()` puts one material in `stock` and frees the slot; `collect()` finishes every done job. The game loop (`forgeTick()`) calls `collect` every frame.
  - **Speed:** `speedFactor(speedLv, frenzy, bonus) = (1 + 0.25 × Forge Speed) × (1 + artifact forge bonus) × (2 while frenzy is on)`. When it changes, `setRate()` re-times the work left in running jobs from now.
    - `f.bonus` is live only, like `rate`. `setBonus` changes it (from `recalc()`), and `fromSave(d, bonus)` takes the loaded artifacts' bonus, because saved ends were planned at the rate that included it.
  - **Frenzy counts only while the page is open and visible.** `forgeTick()` sets it, the `visibilitychange` (hidden) and `pagehide` handlers clear it, and `toSave()` stores ends at the no-frenzy rate.
  - **Clock safety:** a clock behind a job's start reads progress 0. Re-timing and Strikes measure from the start, so a backwards jump never finishes a job early.
  - **Strike:** `strike(f, now, slot)` takes `STRIKE_SECS` (1 s) off the running job, at most `STRIKE_CAP` (5) per `STRIKE_WINDOW_MS` (1000 ms), and never into the past. The Forge panel's Strike button calls it.
  - **Slots:** `BASE_SLOTS` (1) + Extra Slot level.
  - **Upgrades** (`UPG`, bought with juice, cost `ceil(base × grow^level)`):
    - Forge Speed: base 20,000, grow 2.8, max 10.
    - Extra Slot: base 250,000, grow 10, max 3.
    - `upgCost`, `canBuy` and `buy` (which returns the juice to take) are pure.
  - Game hooks in `src/ui.js`: `forgeStart`, `forgeStrike`, `forgeBuy`, `forgeCatchUp` and `forgeTick`. `forgeTick` runs every frame before the HUD update.
  - `FORGE.costText(have, need, id)` reads "2 of 5 Rose Dust". Artifact cards use it for material cost lines, so a real material artifact needs no UI work.
- **Forge panel** (`#forge`, `updateForge()`, data from `forgeView()`): a large panel in the Artifacts family.
  - **Dock button** (`#forgeBtn`, an inked anvil): the same 100-Rose gate as Artifacts, or any forge work in the save.
    - A dot (`#forgeDot`, `setForgeDot`) lights when a job finishes while the panel is closed, including offline, and clears when the panel opens.
  - **Speed line**, e.g. "Forge speed x2.5: level 1, frenzy x2". It shows the total rate, and frenzy appears and disappears live.
  - **Slots:** one row each. Empty, or the material, a bar, time left at the current speed, and a Strike button.
    - Strike works on `pointerdown` (touch and mouse), plus keyboard clicks.
    - It names its slot to the engine, which allows 1 s off per press and at most 5 presses per second; refused presses shake the button.
    - The button is at least 76×52 px and shows a "-1s" float.
    - A mouse or touch press sends pointerdown then a click with `detail` 1, which is ignored, so one press is one Strike. Checked in headless Chrome: one real click, Enter, Space and a touch tap each took exactly 1 s, with one engine call each.
  - **Recipes:** one row per discovered pearl type, then one per alloy whose dusts all come from found types (no pearl picture, no Keep toggle). Each shows the cost, the time at the current speed, the Roses (or other pearls) in the backpack, the material in stock, a Keep toggle and a Start button that uses the first free slot.
  - **Start explains itself:** `startReason()` gives the first cause that applies:
    - "The forge slot is busy" / "All forge slots are busy";
    - short with auto-sell on and the type not kept: "Turn on Keep for Rose Pearls, or turn off auto-sell";
    - kept but not spawning: "... are not spawning right now: unlock them in the shop or add them to your pool";
    - otherwise "Need N more ... in your backpack";
    - for an alloy: "Need N more Blue Dust: make it in the forge" (the first missing dust).
  - **Keep and auto-sell:** the forge spends normal pearls from the backpack, kept or not.
    - With auto-sell on, only kept types ever reach the backpack, so Keep is how to feed the forge.
    - The recipe's Keep toggle calls `setKeep`, the same state as the backpack Keep list.
    - The panel says that kept Rose Pearls are also what the Pink Duck needs, so the forge and the duck compete for them.
  - **Materials and Forge upgrades:** the stock line, then Forge Speed and Extra Slot as shop-style `.up` cards (level, effect, price, flash on buy).
  - The Artifacts panel shows the same stock line (`#artMats`).
  - **Refreshes in place:** rows are rebuilt only when the structure changes (slot count, running slots, discovered types). Bars, text and buttons update every HUD tick. Finished jobs, purchases, Keep changes, Fresh Batch, loads and imports reset the panel's cache.
  - **Duck stash warning** (`stashWarn(m)`, the recipe row's `.frd` line, amber): when a Start would leave fewer of a pearl than an artifact's next craft needs, the row says e.g. "Uses 100 of your 4,200 kept Rose Pearls (the Pink Duck needs 10,000)". It shows only when the player has enough to start, so it covers both "the duck is still unaffordable" and "this Start would make it unaffordable". It never blocks Start. It follows the repeat cost (2,500 once a duck is owned).
  - **Artifact costs** can name materials: `{ kind: 'material', id, qty }` is checked against and spent from `state.forge.stock`. The relics use alloy lines; a test fixture also mixes a dust line and a pearl line.
- **`src/econ.js`** holds the pure economy and no DOM:
  - upgrades: `UPG`, buy `ORDER`, `TOOLS`;
  - **tool unique upgrades:** a `TOOLS` entry can carry `unique: { id, name, desc, base, grow, max, effect }`. It is bought on that tool's page in the Tools panel and priced by `uniqueCost(i, lvl)` (`base × COST_SCALE × grow^lvl`). Its level lives at `state.toolUp[i].u`, next to `p` and `s`, and Fresh Batch wipes it like the others. `stats()` merges `effect(level)` in only for the **equipped** tool with level > 0, so the upgrade works only while that tool is in hand.
    - Only the Steel Pin has one today: **Wide Swing** (`effect` turns on `sweep` and sets `brush`), with the old shop prices (base 35, grow 3.4, max 5).
    - The UI reads the definition (`updateToolPanel`'s `uRow`, and `toolUpgrade()`). Tools without one show the muted "No special upgrade yet" line. Add a tool's upgrade by adding its `unique` entry; the panel needs no new code.
  - **Helpers** (`UPG.auto`) are late game: they need Coral Pearls and cost base 45000 (grow 1.3, max 20), priced so the first helper lands 70–90% of the way to the first Fresh Batch in the sim. Helper Speed still needs Helpers.
  - **Chain Reaction no longer exists.** `tests/econ32.test.js` fails if `src/` or `tools/` mention "chain" outside the save migration that refunds it.
  - the pearl roster: `PEARLS`, with hp, payout and spawn `cap`. **Payouts are derived:** each entry's table value is kept as `baseMult`, and `mult` = `baseMult × PAYOUT_STEEPNESS^rank` rounded to two significant figures (`PAYOUT_STEEPNESS = 1.5`, Rose is rank 0). This gives 1, 7.5, 27, 100, 350, 1,100, 4,000, 14K, 51K and 190K. Change the curve with the constant, not the table;
  - spawn weights (`NEW_BASE`, `typeWeight`);
  - **the global dials** (2026-10-21): `COST_SCALE = 2.5`, Helpers base 45000, `COLLAPSE_MIN_RUN = 5e6` (not scaled by Flavors), and `collapseGain = floor(sqrt(run / COLLAPSE_GAIN_DIV))` with `COLLAPSE_GAIN_DIV = 1.25e6` (exactly 2 Flavors at the floor). `collapseReady` is unchanged;
  - **the pacing dials** (2026-10-22, data only): `FLAVOR_BONUS` 0.1 (was 0.2), `UPG.black.base` 55,000 (was 60,000; level 1 costs 137,500) and `NEW_BASE.black` 0.8 (was 0.15). `NEW_BASE` is exported so the sim can override it. The sim variant `oldDials` replays the old values;
  - frenzy: `stats().frenzyNeed = 200 - 24 × Fuel` (4x the old 50 - 6 × Fuel). It lasts `FRENZY_SECS` (7 s). A tap adds 1 to the meter, a helper pop `HELPER_METER` (0.25). `src/world.js`, `src/ui.js` and the sim read these constants;
  - `FLAVOR_BONUS = 0.1`: what each Flavor adds to every payout (`echoMult = 1 + FLAVOR_BONUS × echoes`). The Fresh Batch text reads it ("Each Flavor adds 10% ..."), so it is never written as a literal;
  - **helpers:** `helperCanHit(kind, power)` (hp ≤ 3 × power) and `helperScore(kind, hpLeft, power)` (payout per remaining hit) are the helper's targeting rules. `stepAuto` in `src/world.js` and the sim both call them;
  - **away bonus rule:** `awayBonus()` pays 50% of `idleRate(S, pool, L, shinyOn)`, capped at 8 h. `idleRate` is `helperIdle(...).rate`, the steady state of helpers alone:
    - a type helpers cannot hit fills its cap, and `trySpawn` turns its share into Rose;
    - pops/s = helper hits ÷ mean hits per pop, or the spawn rate if lower;
    - value = mix × payout × the shiny bonus;
    - frenzy from helper meter credit is blended in.
    - It must stay within 15% of half of the sim's measured helper-only hour (`helperHour` in `tools/sim32.js`) at the first helper, the first Fresh Batch and the cycle 6 Fresh Batch. `tests/away.test.js` enforces this. If the formula drifts from the measurement, fix the formula, not the target;
  - `stats()` and `popValue()`.
  - It is also `require`d by node tests and the sim, so **every economy number lives here**. The number formatters `fmt` / `fmtV` / `fmtX` sit at the bottom of it, outside the `ECON` export. `fmtX` prints payouts (`7.5`, `4,000`, `14K`, `1.5M`); the shop text, the Collection book and the pool cards use it.
- **`src/save.js`** holds pure save helpers with no DOM: `encodeSave` / `decodeSave`, plus `SAVE_VERSION`, `MIGRATIONS` and `migrateSave`.
- **`src/world.js`** holds state, board, spawning (`trySpawn` enforces the per-type cap) and effects.
- **`src/render.js`** draws the canvas.
- **`src/ui.js`** holds the shop, panels, input, save/load, Fresh Batch and the main loop.
- **Fresh Batch:**
  - Code: the `collapseBtn` handler, `finishCollapse()` and `resetRun()` in `src/ui.js`.
  - **Wipes:** juice, run juice, all upgrade levels, tools and tool upgrades, the backpack stacks that are not kept (`clearUnkept()`), and the board.
  - **Keeps:** Flavors (`echoes`), `collapses`, `lifetime`, discoveries (`col`), the pool, settings, every artifact copy and pedestal, the Keep set, kept stacks (normal and shiny) and the whole forge (jobs keep running, dusts and alloys, forge upgrades). Reset save wipes all of it.
- **Save storage:**
  - The `localStorage` key is `poppit.v1`. **Never rename it**: every existing player's save lives there. The key name is not the format version.
  - The JSON inside carries `version`. The current version is `SAVE_VERSION = 7` in `src/save.js`. `serialize()` and `loadState()` live in `src/ui.js`.
  - The game saves every 5 s, after purchases, on `visibilitychange` to hidden, and on `pagehide` (iOS Safari does not reliably fire `visibilitychange` when a tab is closed).
- **Versioning rules:**
  - A save without `version` is version 1.
  - `MIGRATIONS[n]` turns a version n save into version n + 1. `migrateSave` runs every step from the save's version up to `SAVE_VERSION`. The v1 → v2 step grants Blue, marks unlocked and seen types as found, and pools them. The v2 → v3 step refunds Chain Reaction into `sparks` and moves Wide Swing: the refund is the sum of chain's v2 prices for each level below the saved one (base 110, grow 2.5, max 8, COST_SCALE 6, frozen in the step), and `lv.sweep` moves to `toolUp[0].u`. Both `lv.chain` and `lv.sweep` are removed. Run juice and lifetime are not changed. The v3 → v4 step adds `artifacts: {}` and `keep: {}` (keeping objects that are already there). The v4 → v5 step adds an empty forge (`{ slots: [null], stock: {}, lv: { speed: 0, slot: 0 } }`). The v5 → v6 step turns each `id: true` artifact into one Common copy with no perks, active (copy ids 1, 2, ... in key order), so an old duck pays exactly as before. The v6 → v7 step gives every copy `paid` and `locked`: the repeat-craft price (duck 2,500 Rose; the relics their alloy lines), except a Pink Duck's first copy (its lowest id), which gets the first-craft price (10,000). The prices are frozen in the step as of 2026-10-22. Epic and Mythic copies are locked, like new ones; others are not.
  - To change the format: bump `SAVE_VERSION`, add one migration step, and **never edit a step that has shipped**.
  - A save with a version newer than `SAVE_VERSION` is refused with a toast. If it is the stored save, `saveBlocked` stops autosave from overwriting it. Reset save, an import or a restore clears the block.
  - A version that is not an integer ≥ 1, or a save that is not an object, is refused as invalid.
- **Loading is untrusted input:**
  - `loadState(obj)` returns `'ok'`, `'invalid'` or `'newer'`. On anything but `'ok'` it leaves the state untouched.
  - Numbers must be finite and ≥ 0, otherwise they become 0. Levels clamp to 0..max.
  - Tool upgrades clamp to 0..5, the unique level `u` clamps to that tool's own max (0 for tools without one), unknown tool indexes are dropped, and `equip` must be a tool that is owned (or -1).
  - `autoSell` is on unless the save stores `false`. A new game and Reset save also start with it on. Saves written before 2026-10-18 always stored the field, so existing players keep whatever they had, which was usually off.
  - Booleans must be real booleans. `musicVol` must be finite, otherwise it becomes 0.5.
  - The pool keeps only real, discovered pearl ids, without duplicates, and is never empty (it falls back to `pearl`).
  - `col` entries are rebuilt in their known shape, and unknown keys are ignored.
  - `artifacts` goes through `ARTS.fromSave` (see the copies model above). `keep` keeps only known pearl type ids set to `true`. Anything else, including a non-object, is dropped. `serialize()` writes both, so save codes, files, the import backup and Restore carry them.
  - `forge` goes through `FORGE.fromSave` (after the artifacts, for their forge bonus): levels are clamped to their max, `stock` keeps known dusts and alloys with whole counts above 0, and the slot count follows the Extra Slot level. Jobs with an unknown material or bad timestamps are dropped, and an end beyond the start plus the recipe time is clamped.
  - **Offline:** `awayBonus()` (at boot, and on return to a hidden tab) first finishes every job whose end has passed. The toast adds "and N forge jobs finished", or says only that when there is no juice.
- **Save codes:**
  - Format: `POPPIT2:` + base64 of the UTF-8 JSON + `.` + 8 hex digits of FNV-1a over the base64 text. Whitespace is ignored.
  - `decodeSave` returns `null` for a wrong prefix, a bad checksum, bad base64, bad UTF-8, or JSON that is not an object. A truncated code or a single changed character is always caught.
- **Settings → Save:**
  - **Copy save code:** uses `navigator.clipboard`, then a hidden-textarea `execCommand`. If both fail, the code is shown selected in a read-only box.
  - **Download save file:** `poppit-save.txt`.
  - **Paste box:** the Open file picker fills it (files over 1 MB are refused).
  - **Load:** checks the code and shows an in-panel confirm with its juice and Flavors. **Confirm** loads it.
- **Backup:**
  - Before an import, the current raw save (or the serialized state, if nothing is stored yet) is copied to `localStorage` key `poppit.backup`.
  - If a stored save exists and the backup cannot be written, the import is aborted.
  - **Restore previous save** shows only while `poppit.backup` exists. It needs a second click to confirm, loads the backup, and deletes it.
  - **Unreadable stored save:** at boot, `loadStored()` copies a stored save that is not JSON (or not a loadable save) to `poppit.backup` before the fresh game's first save replaces it, and shows a toast. If `poppit.backup` already holds a good save, the raw text goes to `poppit.unreadable` instead, so a good backup is never pushed out.
  - When the backup cannot be loaded, the Restore row says "Your last save could not be read". Restore then shows the raw text, selected, in the read-only box so the player can copy it, and keeps the backup.

  - **Relic scraps refund nothing** at today's prices (40% of 1 or 2 alloys floors to 0). The rows say "Scrap: no refund". Rounding up, or a larger share for materials, would change that; the share is one value (`REFUND_SHARE`).
  - Scrapping changes what a Mythic hunt costs: 33.3 crafts cost 90,833 Rose Pearls on average, and scrapping the other 32.3 copies gives back about 35,300 (4,000 for the first duck, 1,000 for each repeat), so about 55,500 net (61%).
  - The shelf sort is not saved; it resets to Best first on reload.
  - Copy ids can be reused after the newest copy is scrapped (highest + 1).
  - Rarity weights, perk ranges and caps, relic and alloy costs and the relic bonuses are untuned beyond the 2026-10-22 retune; no sim models crafting.
  - **Rolls in numbers** (after the 2026-10-22 retune; `PINK_DUCK_PAYOUT` 1.4, perk stats equally likely):
    - Expected duck payout per craft: Common x1.400, Rare x1.409, Epic x1.428, Mythic x1.470; all crafts x1.408. A Monte Carlo of 1,000,000 rolls agrees (x1.4082).
    - With a payout perk: Rare x1.456 (1.428-1.484), Epic x1.484 (1.442-1.526), Mythic x1.540 (1.470-1.610). Best case x1.610.
    - One Mythic: 33.3 crafts on average, 90,833 Rose Pearls (10,000 + 2,500 per repeat). At the sim's Rose rates: casual 15.4 h, 8.9 h, 6.9 h; engaged 19.2 h, 7.4 h, 11.6 h (first helper, first Fresh Batch, cycle 6).
    - A Mythic with a payout perk: 66.7 crafts, 174,167 Rose Pearls; casual 29.6 h, 17.1 h, 13.2 h; engaged 36.7 h, 14.2 h, 22.2 h.

    - Selling them would have paid 0.44M-1.5M juice, but Roses are only 0.2-0.6% of income at those points, so keeping costs almost nothing per minute.
    - Measured with every type pooled; a Rose-only pool would collect faster.
    - **Some rows look odd** (measured on the 2026-10-21 dials). With the duck, casual cycle 6 takes 85 min and engaged's first Fresh Batch 96 min, against 45 and 49 without it. Each row is one 60-second window from a single seed (frenzy, the board fill and the pearl mix at that moment all move it), so single rows are noisy. Averaging several windows or seeds would be needed before using them for tuning.

- **Sim limitations** (see the report): no backpack selling, the away bonus is reported but never taken, pool never toggled, fixed cell counts per board tier. During a run, helpers get no frenzy meter credit and hit a random pearl they can break; the game (and the sim's helper hour) take the best payout per hit. Switching the run would move the reference pacing numbers. The nothing-to-want columns read 0.0 everywhere (before this change too), so they carry no signal.
